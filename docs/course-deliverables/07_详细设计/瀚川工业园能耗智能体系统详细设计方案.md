# 瀚川工业园能耗智能体系统详细设计方案

> 依据：仓库 `hanchaun-fde` main 分支（HEAD `11d3992`）真实代码。所有表格、清单均从代码提取，未经实现的条目明确标注。ER 图 Mermaid 源码见 `er_diagram.mmd`。

## 1. 总体架构

模块化单体（非微服务），单进程 FastAPI 应用：

```
app/
├── main.py          # 入口：路由注册、限流/指标中间件、错误处理器、静态页
├── api/             # 13 个路由模块（HTTP 层）
├── core/            # 横切：config/security/permissions/ratelimit/token_budget/metrics/llm/guardrail
├── agent/           # Agent 执行核心：loop/harness/tools/specs/guards/confirmation/state
├── rag/             # 知识检索：loader/chunker/embeddings/bm25/retriever/index_manager
├── energy/          # 能源域：data_service/meter_validator/anomaly_detector/report_service
├── db/              # models(23 表)/repo(查询层)/session(WAL+busy_timeout)
├── services/        # chat/kb/prompt/audit 业务服务
├── schemas/         # Pydantic 模型
├── static/          # 用户前端（原生 JS 单页）
└── templates/       # 管理后台（Jinja2 10 页面）
```

分层依赖单向：api → services/agent/energy → core/db。模型（LLM）只经 `app/core/llm.py` 出网，且在 Agent 链路中**无任何写权**。

## 2. FastAPI 设计

| 设计点 | 实际实现 | 代码位置 |
|---|---|---|
| 应用入口 | `app = FastAPI(...)`，启动时建知识库索引、LLM 就绪探测 | `app/main.py` |
| 路由注册 | 13 个 APIRouter：auth/users/chat/agent/anomalies/kb/prompts/sessions/audit/logs/admin + health/metrics | `app/api/*.py` |
| 中间件 | 限流（纯 ASGI，用户 240/min、全系统 1200/min，429+Retry-After）+ 指标计数（纯 ASGI，不缓冲 SSE） | `app/core/ratelimit.py`、`app/core/metrics.py` |
| 异常处理 | 统一 `AppError` 处理器，响应 `{code, message, details}`，中文提示 | `app/errors.py` |
| 依赖注入 | `get_current_user`（JWT Cookie）、`require_permission("xx:yy")`、`require_csrf_header` | `app/api/deps.py` |
| 认证授权 | HttpOnly Cookie JWT + CSRF 请求头双校验；权限码 → 角色 → 用户三级 RBAC | `app/core/security.py`、`permissions.py` |

openapi 实测：45 路径 / 51 操作，清单见 §10。

## 3. Agent Harness（真实执行流程）

核心类 `AgentRunner`（`app/agent/loop.py`）：

1. **入口**：`POST /api/agent/analyze` 建 AgentTask，校验（知识库就绪、会话归属、Agent 开关、日预算、行级范围）；
2. **循环**：`for _ in range(MAX_TOTAL_CALLS)`（=12）：组装消息（系统提示词+对话+工具结果摘要）→ 调 LLM → 解析工具调用或最终回答；
3. **状态管理**：`AgentState`（`app/agent/state.py`）维护 validation_status 状态机与证据池；每轮落 `AgentExecutionLog`（摘要 digest ≤300 字符）；
4. **工具执行**：统一走 `ToolExecutor`（见 §5 五道闸）；工具结果按类型注入上下文；
5. **预算与止损**：单任务 ≤12 次调用、同类工具 ≤3 次（MAX_SAME_TOOL_CALLS）、总时长 180s、单工具输出 60k 字符截断；连续撞闸判"模型陷入错误规划"终止；
6. **产出**：最终回答 SSE 流式下发；报告类任务生成草稿（§6 审核点②）；任务账本（AgentTask/AgentToolCall）落库。

`harness.py` 提供评测用离线确定性规划器（mock 口径下 30 用例可回归）。

## 5. 五道安全闸（guards.py 实际实现）

| 闸 | 触发条件 | 检查内容 | 失败行为 | 审计 |
|---|---|---|---|---|
| 预算闸（先置） | 任务调用次数/时间耗尽 | MAX_TOTAL_CALLS、180s | TERMINATE，任务标预算耗尽 | AgentTask 状态+执行日志 |
| ① 身份与权限闸 | 用户权限码不含工具所需码 | user.permissions ⊇ tool.permission | SCOPE_DENIED/FORBIDDEN，工具不执行 | AgentToolCall 记失败 |
| ② 数据范围闸 | scope 判定位置保留 | guards 层保留判定位置（当前恒通过）；**行级过滤由 API 层强制注入**（阶段11） | （经 API 层）403 | 调用留痕注明 |
| ③ 前置条件闸 | 任务状态机不允许该工具 | 如未查配置不可直接出报告 | TOOL_PRECONDITION_FAILED+缺什么 | AgentToolCall |
| ④ 参数校验闸 | Pydantic 校验失败 | 严格类型/范围，无任意 SQL 通道 | PARAM_INVALID | AgentToolCall |
| ⑤ 输出闸 | 所有工具输出返回模型前 | `_trace` 注入、evidence_id 签发、数值 NumberTrace | 无引用的数值不允许出现在报告中 | 证据池落库 |

结论：五道闸全部真实生效（②经 API 层行级过滤落实），不存在"仅有文件名未接线"的闸。

## 6. 三个人工审核点（实现状态核实）

| 审核点 | 实现 | 阻断效果分析 |
|---|---|---|
| ① 数据质量人工复核 | **已实现**：`detect_force_review` 读工具返回的确定性证据与状态机（不读模型措辞），5 类触发（multiplier_anomaly/version_conflict/data_missing/safety_risk/ownership_unclear）；触发后草稿强制挂 pending_review。用户点"取消"无法抹掉风险（cancel 保留草稿与风险请求号） | 能阻断：草稿状态机不通过不能进入已确认；但"人工修复队列"工作台待开发，复核动作目前只读展示 |
| ② 用户确认提交 | **已实现**：confirm 四重校验（属主/状态/风险请求/内容哈希）、cancel 保留草稿；确认后状态机推进 | 能阻断：不确认则仅存草稿，绝不产生"已确认结论" |
| ③ 授权人员复核与主管签核 | **部分实现（签核写入待开发）**：复核记录只读展示（/api/anomalies/{id}/reviews）、报告导出（md/html，页眉注明待复核草稿）供线下签核；`review_records` 无写入通道 | 不能在系统内阻断业务操作（签核在线下）；SRC 阶段需补写入通道后才形成完整闭环 |

## 7. 数据库设计（23 张表，models.py 实测）

**实体分组**：

| 组 | 表 | 要点 |
|---|---|---|
| 用户权限（6） | User、Role、Permission、UserRole、RolePermission、（scope 在 UserRole.scope_type/scope_values） | RBAC 三级+行级范围 JSON |
| 知识库（2） | KnowledgeDocument、KnowledgeDocumentVersion | 版本链、软删除、内建文档保护 |

## 8. RAG 设计

| 环节 | 实现 | 代码 |
|---|---|---|
| 文档加载 | md/txt 上传，内建文档（knowledge/samples）保护不可删 | loader.py、kb_service |

## 9. 能源分析模块

- **数据服务**（data_service.py）：演示 CSV 读取缓存+`MeterReadingRow` 查询（窗口聚合）；`PROJECT_ROOT` 相对路径。
- **六项校验**（meter_validator.py）：缺失/倍率/量纲/时间连续/版本生效/总分表口径。
- **规则 A**（RuleA_RatioChange）：同表相邻周期倍率或量纲突变检测。
- **规则 B**（RuleB_BalanceDiff）：总表−Σ分表差异率超限检测。
- **适用边界**：规则为确定性保守方法，只覆盖计量类异常（假异常拦截+总分差异）；统计基线类（气温/产量拟合）未实现。产出为"候选异常事件"，最终结论必须经人工确认。

## 11. 前端设计

- **用户端**（app/static/）：原生 JS 单页，知识问答+异常模式双通道、SSE 流式渲染、引用折叠、降级角标；登录页独立。
- **管理后台**（app/templates/，10 页面）：dashboard/users/kb/prompts/anomalies/audit/logs/agent_tasks/agent_logs 等；Jinja2+共享 admin_base。
- 权限差异：admin 可见后台；user 仅问答与自身会话；行级范围影响异常列表可见集。

## 13. 部署设计

Dockerfile（python slim，多阶段省略——单阶段安装依赖+拷贝应用）、docker-compose（应用+卷挂载数据库/缓存/知识库）、.env.example 33 变量（DB_URL、JWT、LLM_PROVIDER/KEY/MODEL、限流、预算、AGENT_ENABLED 等）。单实例约束：SQLite WAL 单写者、内存向量索引、进程内限流——**不支持多副本**（扩容需迁移 PG+外置索引，属 P2）。运行手册见第 9 项。
