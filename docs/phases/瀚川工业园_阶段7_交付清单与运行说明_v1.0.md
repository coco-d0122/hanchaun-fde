## 二、运行说明

```bash
cd backend
../.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 全量回归（4 套，共 83 项断言）
../.venv/Scripts/python scripts/agent_selftest.py        # 阶段6 回归 16 项
../.venv/Scripts/python scripts/harness_selftest.py      # Harness 27 项
../.venv/Scripts/python scripts/confirmation_selftest.py # 人工确认 19 项
../.venv/Scripts/python scripts/harness_scenarios.py     # 三场景 A/B/C/D 21 项（会打印轨迹）
node --check static/app.js                               # 前端语法
```

主要接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/agent/analyze` | Harness 分析（SSE）；`require_confirmation=true` 时下发草稿后暂停 |
| POST | `/api/agent/drafts/{id}/confirm` | 确认提交人工复核（四重校验 + 幂等） |
| POST | `/api/agent/drafts/{id}/cancel` | 取消（不提交报告；强制复核风险独立保留） |
| GET | `/api/agent/drafts/{id}` | 草稿状态 |
| GET | `/api/agent/logs` | 执行日志（用户/时间/任务/工具/轮次/状态筛选） |
| GET | `/api/agent/tasks` / `/{id}` | 任务账本与调用轨迹 |
| GET | `/admin/agent-logs`、`/admin/agent-tasks` | 管理页 |

SSE 事件：`task → round → status / tool_result×(N) → token×(N) → citations → done
→ draft_ready（仅确认模式且生成报告时）`。

前端入口：聊天页切「Agent 深度分析」，或异常面板点「Agent 深度分析」；
报告草稿下方出现「确认提交人工复核 / 取消」按钮。

## 三、三个典型场景的实测执行轨迹

以下轨迹为 `scripts/harness_scenarios.py` 的真实运行输出（离线确定性规划器；
配置 LLM_API_KEY 后由 Function Calling 自主决策，门禁与依赖不变）。

### 场景 A：能源管理知识问答

> 用户：「电表倍率变更后需要检查哪些信息？」

| 轮次 | 模型决策 | 工具返回 | 说明 |
|---|---|---|---|
| 1 | `search_energy_knowledge` | 命中 3 条，依据充足；首条《02_电表倍率与计量单位管理规范》 | 独立只读工具，一轮完成 |
| 2 | 输出最终回答 | — | 「根据园区能源管理知识库，需要检查的信息如下…」+ 引用来源 |

断言：只调用知识检索；无 `query_energy_data` / `get_meter_config` / `detect` /
`generate_anomaly_report` / `request_human_review`；无报告草稿；引用 3 条。

### 场景 B：能耗异常分析与报告提交

> 用户：「帮我分析A栋楼昨天为什么用电量突然增加，并生成异常分析报告」
> 定位：试点数据里含倍率 10→100 变更的 M-002（异常事件 `AN-20261023-0001`）

| 轮次 | 模型决策 | 工具返回 | 说明 |
|---|---|---|---|
| 1 | `query_energy_data` ∥ `get_meter_config` ∥ `get_device_relationship` | 合计 1393.626 kWh；倍率版本 2 个、冲突 2 项；父表/子表关系 | 三个独立只读工具**并行** |
| 2 | `validate_meter_data` | 未通过，问题 2 项（倍率一致性 + 配置版本冲突） | 前置 query+config 已满足 |
| 3 | `search_energy_knowledge` | 命中 3 条（倍率变更管理规范） | 校验未通过 → **detect 被门禁拦截**，发 `gate_blocked` |
| 4 | `generate_anomaly_report` | `pending_check` 待核查报告草稿，NumberTrace 通过 | 只能出待核查结论 |
| 5 | 输出草稿正文（SSE token 流式）→ `draft_ready` | status=pending、force_review=true | **Agent 暂停**，未自动建复核请求 |
| 用户确认 | `POST /drafts/{id}/confirm` | 复核请求 `HR-…`、建议岗位「计量数据工程师」 | 二次校验身份/权限/版本/证据 hash |
| 重复确认 | 同键/异键再次 confirm | 幂等返回同一 `HR-…` | 不重复建单 |

断言：并行只读；检测不跳过校验；确认前 `paused=true` 且无 HR 工具调用；
确认后返回复核请求编号；报告状态 `pending_check`；决策轮次 ≤5；
确认不写 `review_records`、不改异常状态。

### 场景 C：电表倍率异常判断

> 用户：「METER_001的倍率从10变成100，这是不是电表坏了？」
> 假设：模拟数据中没有 METER_001，映射到唯一含该倍率变更的 M-002 以演示真实校验链路

| 轮次 | 模型决策 | 工具返回 | 说明 |
|---|---|---|---|
| 1 | `query_energy_data` ∥ `get_meter_config` ∥ `get_device_relationship` | 电量、倍率版本史、拓扑 | 先取事实 |
| 2 | `validate_meter_data` | 未通过，问题 2 项 | 倍率与电量跳变不吻合、无变更单 |
| 3 | `search_energy_knowledge` | 命中 3 条 | 制度依据 |
| 4 | `request_human_review` | 复核请求 `HR-…`，建议「计量数据工程师」 | 强制复核条件成立，自动触发 |
| 5 | 输出最终回答 | — | 「**不能仅凭倍率变化认定电表损坏**」；区分配置错误/计量口径/真实设备故障；证据不足提示人工核查 |

断言：全程**不调用** `generate_anomaly_report`、无报告草稿；不出现确定性归因；
三类原因齐备；强制复核工具被调用。

### 场景 D（附加）：校验通过的正向门禁路径

> 用户：「分析 M-001 为什么用电量突然增加，并生成异常分析报告」

轨迹：`query/config/relationship`（并行）→ `validate`（通过）→ `detect_energy_anomaly`
（命中 0 条事件）→ `search_energy_knowledge` + `generate_anomaly_report`。
断言：detect 严格在 validate 之后执行，证明依赖门禁在"允许"方向同样生效。

## 五、采用的默认与假设（汇总）

1. **无真实 LLM Key**：先尝试 Function Calling，失败即回落确定性规划器；工具链、门禁、
   日志、预算全部真实执行，只有"决策"与"最终措辞"由确定性代码产出。
2. **数据源只取异常集 CSV**（两份覆盖同一时间窗，合并会产生重复读数）；
   `METER_001` 映射到唯一含 10→100 倍率变更的 M-002；配置/设备台账缺失字段返回 `null`
   并在 `_trace` 注明，不编造。
3. **工具清单 8 个**：阶段6 的 7 个 + 按本轮要求补 `get_device_relationship`（薄封装，
   复用 `get_meter_config` 的同一份拓扑事实）。`create_draft` 在项目中本就是
   `generate_anomaly_report`，无需改名。
4. **决策轮次上限 5**（用户要求）；阶段6 的 12 次工具调用预算保留为二级保护。
5. **人工确认**：前端 Agent 模式统一带 `require_confirmation=true`；只有真正生成报告时
   才建草稿（知识问答/倍率问答不建），场景 C 无草稿但强制复核仍直接调工具。
6. **scope 数据范围**仍按阶段5 预留 `all`；权限闸按权限码执行。
7. **确认的语义**：只创建复核请求，不写签核结论表、不改异常状态；取消时强制复核风险
   独立保留。该边界由自测断言锁定。
8. **前端确认按钮的验证方式**：以合同级测试验证（`draft_ready.actions` 两端点、
   app.js 处理器、CSRF/幂等键）+ HTTP 端点实测；环境未提供无头浏览器，未做像素级截图验证。
