## 二、并发、性能与限流检查清单（5 项）

|---|---|---|---|---|---|---|
| D2-01 | 多用户并发 AI 问答稳定性 | 20~30 人同时提问会打满连接池/线程池，出现 500、SSE 中断或任务串号（不同用户拿到彼此结果） | QA测试工程师＋ DevOps工程师 | 用 `scripts/load_test.py`（Locust/k6 等价脚本）以 30 并发、持续 5 分钟压 `POST /api/chat/stream` 与 `POST /api/agent/analyze`，全程开启 `LLM_PROVIDER=mock` 与 `=openai` 两轮；采集错误率、P95 延迟、SSE 完整率；压测后核对 `agent_tasks` 记录数与请求数一致、无跨用户 `user_id` 错配 | 硬性下限：HTTP 5xx = 0、SSE 异常中断率 <1%、无任务归属错配。建议值（待确认）：30 并发下 P95 首字 <3s、整段 <20s，CPU <80%。**未压测不得宣称满足并发要求** | P0 |
| D2-02 | LLM 调用配额、Token 消耗与费用上限 | Key 泄漏或死循环会让单日费用失控；无上限时一次压测可烧掉整月预算 | AI Agent工程师＋ DevOps工程师 | ① 核对 `LLM_TIMEOUT`、`LLM_MAX_TOKENS` 实际生效（在 `call_llm` 打点记录耗时/token）；② 设置单用户日 Token 上限后，构造连续 50 次问答，观察第 N 次是否被拒绝并给出中文提示；③ 断开外网模拟 LLM 不可用，确认降级为离线模式且前端有"离线模拟模式"角标；④ 统计单次 Agent 任务 token 与费用（任务账本 `agent_tasks` 增列或日志字段） | 单次调用有超时（默认 60s）与 max_tokens 上限；达到日配额时返回明确中文提示（"今日 AI 调用额度已用完，请稍后再试或联系管理员"）且不产生费用；LLM 不可用时 30s 内降级，页面有可见角标；单任务 token 有上限记录 | P0 |

### 7.3 节能收益计算规则（必须遵守）

1. **剥离产量影响**：先算单位产出电耗，再乘实际产量；不得用总电耗直接对比（产量下降也会"省电"）。
2. **剥离非系统因素**：停产检修、设备改造、电价调整、天气（采暖/制冷）需单列说明；无法剥离的月份不计入。
3. **扣除成本**：收益 = 节省电费 − 系统维护费 − 人工复核工时成本 − LLM 调用费。
4. **安全优先**：不得为达成节电目标降低生产保障负荷或突破电气安全限值；涉及安全负荷的调整一律不做。
5. **不作为结算依据**：试点期数据仅用于效果评估，不进入租户结算（系统本身也不具备结算能力）。

**P0 问题处理规则**：发现 P0 → 立即暂停该批次灰度（不必等评审会）→ 2 小时内登记（现象/影响/证据/责任人）→ 修复后重跑对应检查项与 30 条评测 → 由 QA 与电气安全主管双签方可恢复灰度。P0 未闭环不得进入 S6/S8。

**灰度期停止条件（任一触发即停 Agent 通道，保留人工功能）**：
1. 出现违规工具调用成功（写数据/控设备/签核）；
2. 出现跨楼栋/跨租户数据泄漏；
3. 连续 2 个采集周期数据未更新且页面未标"待刷新"；
4. 同一异常在 24 小时内被 AI 反复判定为"已确认"但证据不足；
5. 复核单 24 小时无人接手（值班失守）；
6. 电气安全主管判定存在安全风险（一票停止权）。

## 十、上线审批与责任分工建议

| 角色 | 职责 | 签署物 | 一票否决权 |
|---|---|---|---|
| 能源管理负责人 | 业务验收总责、指标基线与口径确认、复核岗位落实 | 《试点验收报告》《基线确认单》 | 业务口径不成立时可暂停 |
| 电气安全主管 | 安全边界审核、停止条件确认、异常结论抽查 | 《试点上线审批单》 | **有**（安全风险一票停止） |

| 后端/Agent/前端工程师 | 缺陷修复、门禁与降级实现 | 《缺陷修复记录》 | 无 |

**审批留痕方式**：每次上线/灰度/回滚在仓库 `docs/acceptance/` 下新增一条记录（含决策人、时间、版本/Commit、检查项结论、遗留风险与接受人），并把该记录 commit 到仓库——审计证据与代码同源，避免"口头同意"。

**建议排期**：S0~S4 约 5 个工作日（可与缺陷修复并行）；S5 评审 0.5 天；S6 灰度 3~5 天；S7 观察 2 周；S8 验收 2 天。业务效果（BIZ-01~03）需完整 8~12 周数据，不得压缩到 2 周就下结论。
