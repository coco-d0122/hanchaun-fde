# 安全设计与边界（Security）

> 本文只写**代码里真实存在**的防护，以及**明确没有做**的部分。安全声明不能靠"设计上应该"。

## 1. 威胁模型（按现实风险排序）

| # | 威胁 | 现实后果 | 当前处置 |
|---|---|---|---|
| T1 | AI 被诱导修改原始计量数据 / 控制设备 / 自动结算 | 计量记录失去凭据，安全与资金风险 | 工具集无写通道；直调返回 `UNKNOWN_TOOL`；无结算/控制代码 |
| T2 | AI 编造制度条款或异常原因 | 决策被错误依据误导 | 依据覆盖率判定 + 无依据即拒答 + 报告数值溯源 |
| T3 | 用户越权读其他楼栋/租户数据 | 商业信息泄漏 | 服务端 `require_permission` + 会话归属校验；**数据范围 scope 未启用（见 §5）** |
| T4 | 提示词注入（用户输入 / 知识库文档） | 绕过规则、泄露系统提示词 | 硬约束段由代码追加；检索内容视为不可信；工具参数 Pydantic 校验 |
| T5 | 伪造人工审核结果 | 未经签核的结论被当成已确认 | `review_records` 无写入路径；签核接口 405；确认 ≠ 签核 |
| T6 | 密钥泄漏 / 日志泄漏 | 接口被盗刷、令牌被伪造 | 密钥只在环境变量；日志脱敏；仓库无密钥 |
| T7 | 单用户刷接口 / 打满 LLM 配额 | 其他人不可用、账单失控 | 用户级 + 系统级限流；LLM 超时 + 降级 |
| T8 | 上传恶意文档 / 超大文件 | 磁盘打满、索引污染 | 扩展名 + 大小 + 魔数三重校验；软删除；内建文档禁删 |

## 2. 身份与权限

- 密码：bcrypt（cost=12），库中只有 `$2b$` 哈希。登录失败不区分"用户不存在/密码错"。
- 令牌：JWT HS256，8 小时，HttpOnly Cookie；密钥来自 `JWT_SECRET`，未配置则随机生成并落盘
  `.jwt_secret`（已忽略）。篡改 payload 或换密钥重签一律拒绝（有单测覆盖）。
- 权限：13 个权限码 / 2 个角色（`user`、`admin`），**每个管理接口都有 `require_permission` 依赖**。
- **业务签核权 `anomaly:review:submit` 不授予任何角色**（含 admin）。管理员能管账号、
  知识库、提示词、审计，但**不能代替电气安全主管签核**。
- 写操作要求 `X-Requested-With: XMLHttpRequest`（CSRF）；跨站表单带 Cookie 也过不了。

## 3. Agent 的四层约束

1. **工具清单物理封闭**：注册表里只有 8 个工具，全部只读语义（其中有 1 个"只增不改"的
   复核请求）。名字不在注册表 → `UNKNOWN_TOOL`，并写入 `agent_tool_calls`（status=rejected）。
2. **依赖门禁**：`detect` 必须 `validation_status=passed`；`report` 必须有证据且数值可溯源。
   门禁在 `app/agent/dependencies.py` 与 `guards.py`，不在提示词里。
3. **状态机单一写者**：`app/agent/state.py` 只允许 `pending_analysis → pending_review`，
   模型不能直接改异常状态、不能写 `review_records`。
4. **可追责**：每次工具调用落 `agent_tool_calls`（参数摘要、耗时、状态、错误码），
   任务落 `agent_tasks`，执行日志落 `agent_execution_logs`。**判断"是否违规"看日志，不看模型自述。**

## 4. 内容安全

- **系统提示词硬约束**：模板存数据库、可被管理员修改，但渲染时由代码追加
  "系统级硬性约束"段（不编造数据、不越过工具、不做结论定性）。把模板改成"可以编造"也删不掉。
- **知识库内容视为不可信外部数据**：检索片段只作为依据，不作为指令；文档里的"忽略以上规则"
  不会改变工具门禁（有评测用例覆盖）。
- **引用可核**：回答带 `source_file / heading_path / excerpt`；报告每个数值必须能在证据中找到，
  否则整篇退回（`NUMBER_TRACE_FAILED`）。
- **不做定性结论**：倍率变化只产出"待核查"，不认定"电表故障"。

## 6. 数据与隐私

- 仓库内全部是**模拟数据**（240 表、2026-10-23 一天、6 份模拟制度），不含任何真实园区记录、
  租户名称或个人信息。
- 真实接入后：读数、租户、设备台账属商业敏感数据，仓库必须保持 Private，且导出/截图需审批。
- 日志保留 90 天（`LOG_RETENTION_DAYS`），到期由启动清理删除；归档责任人与删除审批人
  尚未书面确认（阶段9 A-06）。

## 7. 事故响应（简版）

1. **发现违规工具调用成功** → 立即 `AGENT_ENABLED=false`（或停 Agent 路由），保留人工功能。
2. 导出 `agent_tasks` / `agent_tool_calls` / `audit_logs` 作为证据（只读，不改）。
3. 定位是"门禁失效"还是"新增了未审计工具"，修完必须重跑 30 条评测 + 4 套自测。
4. 涉及数据泄漏 → 通知能源管理负责人与电气安全主管，按阶段9 停止条件处理。
5. 密钥疑似泄漏 → 立即轮换 `LLM_API_KEY` / `JWT_SECRET`，并强制所有会话重新登录。

`AGENT_ENABLED=false`（环境变量）可只关 Agent 分析：`/api/agent/analyze` 返回 503 +
中文说明，登录、异常列表、会话、复核记录照常可用；已有任务与复核单状态不受影响。
这是"停 AI 不停系统"的最小实现，也是阶段9 D5-05 的落地。
